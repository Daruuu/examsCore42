De un main.c básico a un servidor TCP con varios clientes

Guía práctica para entender qué hacen las funciones de C/POSIX, qué partes de subject/main.c se pueden reutilizar y qué debe añadirse para implementar correctamente mini_serv.

1. La idea del ejercicio

El programa es un servidor TCP de chat. Escucha en 127.0.0.1, acepta clientes, les asigna un ID y retransmite sus líneas a los demás.

socket
→

→

→

→

cliente listo
→

→

Idea clave: TCP es un flujo de bytes. Un recv() no representa necesariamente una línea completa. Por eso cada cliente necesita un buffer propio.

2. Funciones que debes entender

Red · creación

socket()

Crea el descriptor que representa el socket. Con AF_INET y SOCK_STREAM se usa TCP sobre IPv4.

Red · dirección

bind()

Asocia el socket con una dirección IP y un puerto. El ejercicio exige escuchar solo en 127.0.0.1.

Red · escucha

listen()

Convierte el socket en servidor y prepara una cola para conexiones pendientes.

Red · conexión

accept()

Acepta una conexión pendiente y devuelve un nuevo descriptor para ese cliente. El socket servidor permanece abierto.

Multiplexación

select()

Espera hasta que uno de los descriptores esté listo para leer. Permite atender a muchos clientes en un único bucle.

Red · entrada

recv()

Lee bytes de un cliente. 0 indica desconexión; un valor positivo indica datos recibidos.

Red · salida

send()

Envía datos a un cliente. En esta solución se usa para difundir avisos y mensajes.

Recursos

close()

Cierra el descriptor de un cliente desconectado. Es necesario para no producir fugas de descriptores.

Memoria

malloc() · calloc()

Reservan memoria para concatenar datos y conservar la parte del buffer que aún no se ha procesado.

Memoria

free()

Libera buffers de clientes desconectados y líneas ya enviadas.

Cadenas

strlen() · strcpy() · strcat()

Calculan tamaños, copian el resto del buffer y concatenan fragmentos recibidos.

Conversión y salida

atoi() · sprintf() · write()

Convierten el puerto, construyen avisos y escriben errores en stderr.

Ejemplos tomados de la solución

La descripción anterior indica la responsabilidad de cada función. Estos ejemplos muestran ahora cómo se conectan entre sí dentro de miniserver.c.

1. Crear, configurar y poner a escuchar el servidor 
sock = socket(AF_INET, SOCK_STREAM, 0);
if (sock < 0)
    fatal();

memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_addr.s_addr = inet_addr("127.0.0.1");
addr.sin_port = htons(atoi(argv[1]));

bind(sock, (struct sockaddr *)&addr, sizeof(addr));
listen(sock, 128);

socket() crea el descriptor. bind() asocia ese descriptor con una IP y un puerto. listen() indica que el descriptor será un socket servidor. Todavía no existe ningún cliente: solo se está preparando el punto de entrada.

Estado: sock es el descriptor servidor. Los futuros clientes tendrán otros descriptores distintos.
2. Aceptar un cliente sin perder el socket servidor 
if (fd == sock) {
    int client = accept(sock, 0, 0);
    if (client < 0)
        continue;

    ids[client] = next_id++;
    bufs[client] = NULL;
    FD_SET(client, &all);
}

Cuando fd == sock, significa que hay una conexión pendiente. accept() devuelve un descriptor nuevo para hablar con ese cliente. El descriptor sock sigue reservado para aceptar futuras conexiones. 

sock = 3       /* servidor */
client = 5     /* cliente nuevo */
ids[5] = 0
bufs[5] = NULL
3. Vigilar muchos descriptores con select() 
FD_ZERO(&all);
FD_SET(sock, &all);
maxfd = sock;

while (1) {
    readfds = all;
    select(maxfd + 1, &readfds, 0, 0, 0);

    for (fd = 0; fd <= maxfd; fd++) {
        if (!FD_ISSET(fd, &readfds))
            continue;
        /* fd está preparado para ser atendido */
    }
}

all es la lista permanente de descriptores activos. readfds es una copia temporal porque select() modifica el conjunto que recibe. Después de la llamada, FD_ISSET() permite saber qué descriptores están preparados.

Error habitual: no llames a select() directamente con all, porque perderías la lista completa después de la primera iteración.
4. Interpretar recv(): datos, desconexión o error 
n = recv(fd, buf, 1000, 0);

if (n <= 0) {
    /* n == 0: el cliente cerró la conexión.
       n < 0: ocurrió un error. */
    close(fd);
    FD_CLR(fd, &all);
} else {
    buf[n] = 0;
    /* Hay n bytes válidos en buf. */
}
ResultadoInterpretaciónAcción
n > 0Se recibieron bytes.Acumularlos y buscar líneas.
n == 0El cliente se desconectó.Avisar, liberar memoria y cerrar.
n < 0Error de lectura.La solución lo trata como desconexión.
5. malloc(), calloc() y free() en los buffers 
/* str_join(): reserva un buffer mayor */
newbuf = malloc(strlen(buf) + strlen(add) + 1);
strcat(newbuf, buf);
strcat(newbuf, add);
free(buf);

/* extract_message(): conserva lo que queda después de '\n' */
newbuf = calloc(1, strlen(*buf + i + 1) + 1);
strcpy(newbuf, *buf + i + 1);
*msg = *buf;
*buf = newbuf;

/* main(): libera la línea cuando ya fue enviada */
free(line);

str_join() crea un buffer nuevo porque el anterior puede no tener espacio suficiente. extract_message() separa la línea extraída del resto. La memoria transferida a line se libera después de send_all().

Regla de propiedad: toda memoria reservada con malloc() o calloc() debe terminar en un free(), incluso cuando el cliente se desconecta antes de completar una línea.
6. De fragmentos TCP a una línea completa 
/* Primera recepción */
buf = "hel";
bufs[5] = str_join(NULL, buf);
/* bufs[5] == "hel" */

/* Segunda recepción */
buf = "lo\n";
bufs[5] = str_join(bufs[5], buf);
/* bufs[5] == "hello\n" */

while (extract_message(&bufs[5], &line) == 1) {
    sprintf(msg, "client %d: %s", ids[5], line);
    send_all(5, msg);
    free(line);
}

El primer recv() no contiene una línea completa, por lo que no se envía nada. El segundo completa hello\n y entonces extract_message() puede producir una línea válida.

7. send() y send_all(): quién recibe el mensaje 
void send_all(int except, char *msg)
{
    for (int fd = 0; fd <= maxfd; fd++) {
        if (ids[fd] != -1 && fd != except)
            send(fd, msg, strlen(msg), 0);
    }
}

sprintf(msg, "client %d: %s", ids[fd], line);
send_all(fd, msg);

Si el cliente 5 envía hola\n, se construye client 0: hola\n si su ID es 0. El parámetro except vale 5, por lo que el cliente emisor no recibe una copia de su propio mensaje. 

cliente 3  ← recibe
cliente 5  ← emisor, excluido
cliente 7  ← recibe
8. Error fatal y limpieza al desconectar 
void fatal(void)
{
    write(2, "Fatal error\n", 12);
    exit(1);
}

/* Al desconectar fd */
sprintf(msg, "server: client %d just left\n", ids[fd]);
send_all(fd, msg);
free(bufs[fd]);
bufs[fd] = NULL;
ids[fd] = -1;
FD_CLR(fd, &all);
close(fd);

fatal() se usa para errores que impiden continuar, como no poder crear el socket o reservar memoria. La desconexión de un cliente no es un error fatal del servidor: se limpia únicamente el estado de ese cliente y el bucle continúa atendiendo a los demás.

¿Qué hacen FD_SET, FD_ZERO y FD_ISSET?

Son macros de fd_set, no llamadas de sistema independientes: FD_ZERO vacía un conjunto, FD_SET añade un descriptor y FD_ISSET comprueba si select() lo marcó como listo.

3. Qué reutilizar del main.c entregado

El enunciado dice expresamente que el archivo base puede contener funciones prohibidas o código que no debe estar en la entrega final. No es una solución completa para copiar; es un punto de partida.

4. Implementación paso a paso

  1. Validar argumentos.
    Exigir exactamente un puerto y escribir Wrong number of arguments\n si falta o sobra.
  2. Crear el socket.
    Usar socket(AF_INET, SOCK_STREAM, 0) y tratar el error antes de aceptar conexiones.
  3. Configurar la dirección.
    Escuchar solo en 127.0.0.1 y convertir argv[1] al puerto.
  4. Hacer bind() y listen().
    Si fallan, llamar a la rutina de error fatal.
  5. Inicializar el estado.
    Marcar ids[fd] = -1, añadir el socket servidor a all y guardar maxfd.
  6. Esperar con select().
    Copiar all a readfds, porque select() modifica el conjunto recibido.
  7. Aceptar clientes.
    Si el descriptor listo es el socket servidor, llamar a accept(), asignar next_id++ e inicializar su buffer.
  8. Leer clientes existentes.
    Con recv(), un resultado positivo significa datos; cero significa desconexión.
  9. Acumular bytes.
    Usar str_join(bufs[fd], buf), porque un mensaje puede llegar en varios fragmentos.
  10. Extraer todas las líneas.
    Repetir extract_message() mientras devuelva 1, anteponiendo client %d: .
  11. Difundir y limpiar.
    Enviar a todos excepto al emisor, liberar cada línea y liberar el buffer al desconectar.

Estado mínimo por descriptor

int ids[65536];
char *bufs[65536];
fd_set all;
int maxfd;
int next_id;

/* ids[fd]  = ID visible del cliente o -1 si está libre
 * bufs[fd] = datos recibidos aún no terminados en '\n'
 */

5. Cómo se procesa un mensaje

Supón que el cliente 2 escribe dos líneas, pero TCP las entrega en fragmentos:

recv() #1: "hel"
recv() #2: "lo\nsegunda línea\n"

bufs[2] después del primer recv(): "hel"
bufs[2] después del segundo recv(): "hello\nsegunda línea\n"

extract_message() se ejecuta en un bucle:

while (extract_message(&bufs[fd], &line) == 1) {
    sprintf(msg, "client %d: %s", ids[fd], line);
    send_all(fd, msg);
    free(line);
}
Primera iteración

line = "hello\n"

Se envía client 2: hello\n y el buffer conserva la segunda línea.

Segunda iteración

line = "segunda línea\n"

Se envía la segunda línea y el buffer queda vacío.

Fin

return 0

No hay otra línea completa; el bucle termina y el buffer vacío se libera.

Regla de difusión: los avisos de llegada y salida se envían a los clientes que ya estaban conectados; los mensajes de un cliente se envían a todos los demás, nunca al emisor.

Abre varias terminales y conecta clientes:

7. Checklist final

  • El programa recibe exactamente un puerto.
  • Solo escucha en 127.0.0.1.
  • Usa select() y no espera bloqueado a un único cliente.
  • El primer cliente recibe el ID 0 y los siguientes IDs incrementales.
  • Existe un buffer independiente para cada descriptor.
  • Se procesan tanto mensajes fragmentados como varias líneas juntas.
  • El emisor no recibe su propio mensaje.
  • Se notifican las llegadas y las desconexiones.
  • Se liberan líneas, buffers y descriptores.
  • No quedan printf() de depuración ni código del servidor de un solo cliente.
  • Las funciones usadas cumplen la lista permitida por el subject.
